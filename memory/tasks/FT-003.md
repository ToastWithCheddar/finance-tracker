# TaskSpec: FT-003 — Transactions Grouped Fetch Support

- ID: FT-003
- Purpose: Support grouped transactions (by date/category/merchant) using backend `group_by` and return a dedicated grouped structure without breaking existing callers.

## Context
- Backend GET `/api/transactions` returns grouped data when `group_by != 'none'`.
- Current `getTransactions` returns a flat list structure and is used widely; avoid changing its return type.

## Files To Touch
- `frontend/src/services/transactionService.ts`
- (Optional) `frontend/src/hooks/useTransactions.ts` if a grouped hook is needed later (not in this task).

## Exact Changes
1) Add a new method in `TransactionService`:
   - `async getTransactionsGrouped(filters: TransactionFilters & { group_by: 'date' | 'category' | 'merchant' }, options?: { useCache?: boolean; context?: ErrorContext }): Promise<TransactionGroupedResponse>`
   - Build query params per contract: `start_date`, `end_date`, `account_id`, `category_id`, `group_by`, `limit`, `offset`, etc.
   - Call the same endpoint `'/'` and map the grouped payload:
     - For each group in `response.groups`, map `transactions` with `toTransactionView`.
     - Return `TransactionGroupedResponse` as defined in `frontend/src/types/transaction.ts`.

2) Do NOT change the existing `getTransactions` behavior/signature.

## Acceptance Criteria
- New method `getTransactionsGrouped` exists and returns a properly adapted grouped response.
- Type-check passes: `npm --prefix frontend run type-check`.

## Pitfalls
- Do not break `getTransactions` return type.
- Ensure params use `limit/offset` and contract naming (e.g., `start_date`, `category_id`).
