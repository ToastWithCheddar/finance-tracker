# TaskSpec: FT-005 — Contract Param Sweep (Frontend Services)

- ID: FT-005
- Purpose: Replace ad-hoc query/body keys in frontend services with contract-aligned names from OpenAPI; reduce BE/FE drift.

## Scope
- Services under `frontend/src/services/*.ts` (accounts, budgets, categories, merchants, ml, saved filters, notifications, timeline, etc.).
- Compare each call to OpenAPI (`memory/contracts/backend_openapi.json`) and generated types (`frontend/src/api/generated/types.ts`).

## What To Do
- For each service method that calls the API:
  - Confirm endpoint path and HTTP method matches OpenAPI paths.
  - Align query/body parameter names with the contract (snake_case on the wire).
  - Keep view models and internal TS interfaces camelCase; only the wire format changes.
- Common fixes to look for:
  - `start_date`/`end_date` (not `dateFrom`/`dateTo` on the wire)
  - `min_amount_cents`/`max_amount_cents` (not `min_amount`/`max_amount`)
  - `search_query` (not `search`)
  - Pagination: `limit`/`offset` (derive from `page`/`per_page` where needed)
  - Flags: `is_recurring`, `is_transfer`, `status`

## Files To Touch
- Only service files with mismatches (do not refactor unrelated code).

## Steps
1) For each service file, locate API calls and compare to `types.ts` operations and params.
2) Update param mapping to contract names; preserve existing method signatures.
3) Keep or add minimal adapters where necessary (DTO → view model), but avoid broad refactors.
4) Re-run type-check and smoke.

## Acceptance Criteria
- No ad-hoc param names where the OpenAPI defines a canonical name.
- `npm --prefix frontend run type-check` passes.
- `./scripts/smoke.sh` passes.

## Pitfalls
- Do not change public method signatures unless provably unused.
- Do not guess fields; if a mismatch is unclear, surface it for a spec update.
- Keep changes minimal; avoid churn in components/hooks.

## Validation Commands
- `npm --prefix frontend run type-check`
- `./scripts/smoke.sh`
