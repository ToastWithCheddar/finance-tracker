# FT-001 — Generate FE client/types from OpenAPI and refactor Transactions list

Purpose: Use backend OpenAPI to generate TypeScript types/client and refactor the Transactions list fetch to rely on generated types + a thin adapter.

Context:
- Backend is FastAPI and serves OpenAPI at `/openapi.json`.
- FE currently uses `src/services/transactionService.ts` with ad-hoc DTO normalization.
- Contract-first will reduce drift and simplify future changes.

Files to touch:
- `memory/contracts/backend_openapi.json` (export only; no manual edits)
- `frontend/src/api/generated/types.ts` (generated)
- `frontend/src/api/generated/client.ts` (generated placeholder already scaffolded)
- `frontend/src/api/adapters/transaction.ts` (new adapter)
- `frontend/src/services/transactionService.ts` (min refactor to use adapter/types for list)

Contracts:
- GET `/api/transactions` returns a paginated list; accept query params: `page`, `per_page`, `start_date`, `end_date`, `account_id`, `category_id`, `merchant`, `min_amount`, `max_amount`, `search_query`, `transaction_type`.
- Use the exact shapes from the exported OpenAPI (do not guess field names). If the spec lacks any of these, flag and we will update the backend routes or spec accordingly.

Steps:
1) Export spec: `curl -s http://localhost:8000/openapi.json > memory/contracts/backend_openapi.json`.
2) Generate types: `./scripts/types-from-openapi.sh`.
3) Create adapter: `frontend/src/api/adapters/transaction.ts` exposing `toTransactionView(dto)`, `toTransactionList(response)` using generated types.
4) Update `getTransactions` in `frontend/src/services/transactionService.ts` to:
   - Call `apiFetch('/api/transactions?...')` or use a generated typed function if present.
   - Use the adapter to map DTOs → view models instead of inline normalization.
   - Keep method signature stable for now.
5) Do not refactor other methods yet (create/update/delete) — separate tasks.

Acceptance criteria:
- `./scripts/types-from-openapi.sh` generates `frontend/src/api/generated/types.ts` without errors.
- Transactions page still loads with the same UI but now uses the adapter for list mapping.
- No TypeScript errors in `npm run type-check`.
- `memory/integration-map.md` references the new adapter file.

Pitfalls:
- Ensure the FE base URL includes `/api` (default set in `envValidation.ts`).
- Date fields: treat backend date as string; do not coerce to Date in types.
- Amount fields may be cents or decimals; rely on contract, do not guess.

Memory updates:
- Update `memory/integration-map.md` to add the adapter path under Transactions.
