# TaskSpec: FT-004 — Wire Transactions UI to Grouping

- ID: FT-004
- Purpose: Add a lightweight UI control to switch grouping (none/date/category/merchant) and display grouped results using the new `getTransactionsGrouped` without breaking existing flat view.

## Context
- `TransactionService.getTransactionsGrouped` exists and returns adapted `TransactionGroupedResponse`.
- Current Transactions page uses flat list (`getTransactions`). We’ll add a toggle and render a simple grouped view for one grouping (e.g., by date) first.

## Files To Touch
- `frontend/src/pages/Transactions.tsx`
- `frontend/src/components/transactions/TransactionFilters.tsx` (if adding a grouping selector fits better here)
- (Optional) new lightweight component: `frontend/src/components/transactions/TransactionGroup.tsx`

## Exact Changes
1) UI control
- Add a simple select or buttons: None | Date | Category | Merchant.
- Propagate selected `group_by` to the data hook/service call.

2) Data fetch
- When `group_by !== 'none'`, call `transactionService.getTransactionsGrouped({ ...filters, group_by })`.
- When `group_by === 'none'`, keep existing flat fetch path.

3) Rendering
- For grouped data, render groups with a header (group key + total) and the transactions mapped beneath.
- Keep the existing flat list code path intact when grouping is none.

## Acceptance Criteria
- Grouping control switches between flat and grouped views.
- Grouped view renders without TypeScript errors and shows adapted transactions.
- Existing filters (date range, category) continue to apply.
- No regressions in flat view.

## Pitfalls
- Keep changes minimal; avoid broad refactors.
- Preserve pagination UX; it’s acceptable to show simple next/prev for grouped view initially.
