# ML-worker snapshot — `ml-worker/`

Celery worker, Python 3.11, sentence-transformers (`all-MiniLM-L6-v2`), ONNX runtime, optional A/B framework. **Most of the optimization stack is dead code.**

## Service shape

The ml-worker is **not an HTTP service**. Despite `docker-compose.yml:90` mapping port 8001, the container `CMD` is:
```
celery -A worker worker --loglevel=info --concurrency=2 --max-tasks-per-child=1000
```
(`Dockerfile:40`). Broker = Redis (`worker.py:24,28`). Backend submits via `celery_app.send_task('worker.<task>')`.

## Tasks (`worker.py`)

- `classify_transaction` (`:115-170`) — single inference. Creates a **new asyncio event loop per call** (`:122-135`) before running async code. Falls back to direct sync `classifier.classify_transaction` because `production_orchestrator` is `None` (`:38, 154-165`).
- `batch_classify_transactions` (`:172-202`) — batch path; vectorized cosine sim (`ml_classification_service.py:1015-1058`).
- `add_category_example`, `health_check`, `get_production_metrics`, `create_onnx_models`.

## Model loading

`worker_ready` signal (`worker.py:71-113`):
- `_is_light_startup` always returns True (`:40-42`) → orchestrator never initialized.
- Loads sentence-transformer model from `MODELS_DIR=/app/models` → mounted from `./ml_models` (`docker-compose.yml:85,88`).
- Loads or rebuilds prototypes from `models/category_prototypes.pkl` / `default_categories` (`ml_classification_service.py:902-925`).
- Background daemon thread builds base + dynamic-q8 ONNX if missing (`worker.py:45-67, 109`).

## Few-shot prototypes

`ml_classification_service.py` (~1150 LOC):
- ~825 lines of hardcoded `default_categories` examples (`:41-865`).
- Prototype = `np.mean(embeddings, axis=0)` per category (`:917-918`).
- `classify_transaction` (`:954-993`) computes cosine sim to each prototype.
- `batch_classify` (`:995-1058`) is correct vectorized matmul.
- **`confidence_level` hardcoded to `"high"`** (`:984, 1043`) — comment "Demo mode: always use highest probability prediction." Downstream confidence-threshold logic and Prometheus labels become useless.

## Optimized inference engine — DEAD CODE

`optimized_inference_engine.py`:
- Embedding cache (max 10k, **FIFO not LRU**, `:204-209`).
- Thread pool with `os.cpu_count()` workers (`:63`).
- ONNX session init (`:164-186`), warmup (`:148-162`).
- Instantiated only inside `ProductionOrchestrator.__init__` (`production_orchestrator.py:43`).
- **Orchestrator never created** → none of this runs.

## A/B testing framework — DEAD CODE

`ab_testing_framework.py:88-340` — experiment lifecycle, hash-based traffic split, scipy stats. Only consumed by orchestrator (also dead). `ab_test_results/` is empty.

## Monitoring — DEAD CODE

`model_monitoring.py:108-156`:
- Prometheus metrics: `ml_inference_duration_seconds`, `ml_predictions_total`, `ml_model_accuracy`, `ml_memory_usage_bytes`, `ml_cpu_usage_percent`, `ml_cache_hit_rate`, `ml_error_rate`.
- `start_http_server(prometheus_port=8000)` — **collides with backend port** if same network namespace.
- Started only by orchestrator → never starts. **No `/metrics` endpoint exists.**

## ONNX artifacts

- `ml_models/production/transaction_classifier.onnx` — 91 MB (FP32)
- `ml_models/production/transaction_classifier_dynamic_q8.onnx` — 23 MB
- `ml_models/production/transaction_classifier_static_q8.onnx` — 23 MB
- All generated by background thread or `create_onnx_models` Celery task; **never used at inference time** because the live path goes through PyTorch sentence-transformers.

## Model weight duplication

`all-MiniLM-L6-v2` weights tracked in Git **three times** (~270 MB total):
- `ml_models/all-MiniLM-L6-v2/` (mounted into ml-worker at `/app/models`)
- `ml-worker/models/all-MiniLM-L6-v2/` (committed; baked into image)
- `ml-worker/model_cache/models--sentence-transformers--all-MiniLM-L6-v2/` (HF cache layout, also committed)

`ml-worker/.dockerignore` does NOT exclude `models/` or `model_cache/`, so both ship inside the image too.

## Concurrency & memory

- `--concurrency=2` prefork. Each child loads full model (~400 MB resident with PyTorch + transformers).
- `--max-tasks-per-child=1000` recycles child after 1000 tasks.
- `TOKENIZERS_PARALLELISM=false` (`worker.py:10`).
- CPU forced via `CUDA_VISIBLE_DEVICES=""` (`worker.py:12`).
- No `--prefetch-multiplier` tuning, no `--max-memory-per-child`.
